# 红外相机网络 · 训练后权重量化

一个只用 Python + numpy 的训练后权重量化工具：按列量化权重，用少量校准数据
把每一列的舍入误差按输入统计矩阵分摊到尚未量化的列上，并在网页上把整个过程
可视化。

模型是自己搭的小卷积 + 全连接网络（1×32×32 输入，8 类），数据是按红外相机
场景合成的灰度图（几何形状 + 背景杂斑 + 噪声）。

## 快速开始

```bash
python scripts/train_model.py        # 训练并缓存模型 -> out/model.npz（约 1 分钟）
python scripts/run_experiments.py    # 跑实验 -> out/experiments.json + web/data.json + 导出包
python -m http.server 8000           # 然后打开 http://localhost:8000/web/
python -m pytest tests/ -q           # 52 个测试
python scripts/check_export.py       # 单独核对打包推理与浮点模拟
```

`web/index.html` 会依次尝试 `data.json`、`../out/experiments.json`、
`out/experiments.json`，因此从仓库根或 `web/` 启动静态服务器都能打开。

## 方法

**层目标函数。** 对一个权重矩阵 `W`（行 × 列）和该层的校准输入 `X`（样本 × 列），
层的平方输出误差是

```
Obj(Wq) = Σ_r 1/S ‖(Wq_r − W_r) Xᵀ‖²  =  Σ_r (Wq_r − W_r) H (Wq_r − W_r)ᵀ
H = XᵀX / S
```

`H` 就是输入的二阶统计矩阵，目标函数对权重各行解耦。

**逐列量化 + 误差分摊。** 按某个顺序一列一列地把权重舍入到量化网格上。第 `j` 列
舍入后，把它的误差 `e` 压到还没量化的列上：

```
Wq[:, F] -= e · H⁻¹[j, F] / H⁻¹[j, j]      （F 为尚未量化的列）
```

这是给定已固定前缀时剩余列的最优调整，本步引入的目标增量恰为
`‖e‖² / [H⁻¹]jj`。实现上用的是 `H⁻¹` 的**上三角 Cholesky 因子** `U`（`H⁻¹ = UᵀU`）：
对每个后缀 `F`，`(H_FF)⁻¹ H_Fj = U[j, F] / U[j, j]` 精确成立，所以
`inc = ‖e‖² / U[j,j]²`、修正系数 `U[j, F] / U[j, j]`。测试里逐步骤的目标增量
与真实目标函数相等到机器精度（见 `tests/test_quantize.py`）。

> 注意：直接用 `H⁻¹` 的行做修正只在第一列精确；从第二列起必须用
> `H⁻¹ = UᵀU` 的因子，这一点在开发中实测确认过。

**数值与性能。**
- `H` 对称化后加 `damp · mean(diag H)` 的相对阻尼，输入共线、出现死通道时仍正定；
- Cholesky 失败时自动加大抖动重试，主元有下限，修正不会发散；
- 每步只在“尚未量化的后缀”上做一次 rank-1 更新，4096 列的层约 2.6 秒
  （1536 列 < 0.5 秒，测试里有 30 秒上限的保护）。

**分组量化。** 每 `group_size` 列共享一个缩放因子和零点，由该组内权重的实际范围
决定（非对称：`scale=(max−min)/(2^b−1)`，`zero=round(−min/scale)`；对称：零点固定
在 `2^(b−1)`，范围由 `max|w|` 决定）。支持 3 / 4 / 8 比特。

**量化顺序。** `identity`（原始列序）、`diag`（按 `H` 对角元从大到小，先量化影响
大的列）、`diag_reverse`、`random`（固定种子）。

**整网顺序量化。** 按执行顺序逐层处理；第 k 层的校准输入来自**前面已经量化好的
层**的输出，因此深层能看到浅层注入的误差。卷积层展开成 `(out_ch, in_ch·k·k)` 的
矩阵乘，和全连接层走同一套代码。

**导出。** `out/export/<tag>/bundle.npz` 内含位打包的整数码、每组 `scale`/`zero`、
`bias` 和 `manifest`；同目录 `infer.py` 只依赖 numpy，反量化表达式与模拟器完全
一致，`bundle_forward_code()` / `scripts/check_export.py` 验证 logits 逐元素相同
（实测最大差 1.4e-14，来自 float64 求和顺序，argmax 完全一致）。

## 实验结论

模型：浮点测试准确率 **97.80%**（6000 训练 / 1500 测试 / 256 校准，种子固定）。

| 比特 | 网格 | GPTQ | 四舍五入 | 差值 |
|-----|------|------|---------|------|
| 8 | 非对称 | 97.80% | 97.73% | +0.07 |
| 8 | 对称 | 97.73% | 97.67% | +0.07 |
| 4 | 非对称 | 97.53% | 97.20% | **+0.33** |
| 4 | 对称 | 97.60% | 97.00% | **+0.60** |
| 3 | 非对称 | 96.00% | 90.33% | **+5.67** |
| 3 | 对称 | 97.00% | 91.73% | **+5.27** |

整网 logits MSE（4bit 非对称）从 3.29 降到 1.32；3bit 下从 36.6 降到 4.6。
逐层看，补偿把层目标函数压低 1.1×（conv1）到 23×（fc1），层越宽、输入相关性
越强收益越大。8bit 时两种方法都几乎无损，差距很小；4bit/3bit 补偿始终明显占优。

**小矩阵穷举验证**（`tests/test_quantize.py::test_near_bruteforce_optimum`）：
在 4 列、3/4 比特、输入相关性 0.6/0.8 的小矩阵上，对每一行穷举所有
`2^(b·cols)` 种量化组合取最小误差，工具结果平均只比全局最优差 **12% 左右**，
而四舍五入平均差 1.4–2.9 倍；工具在全部样本上都不劣于四舍五入。差距来自
“逐列贪心”本身——每步只在给定前缀下最优，和整行全局最优之间还有一段。

排序影响：对角线顺序 97.73% > 随机顺序 97.60% > 原始顺序 97.53%。差别不大，
因为该网络的输入统计矩阵已经接近对角，顺序能腾挪的余地有限。

## 已知边界

- 逐列贪心不是整行全局最优；穷举只能在小矩阵上做，工具与其差距约 10–20%。
- 补偿可能会把权重推出该组 scale/zero 的覆盖范围（固定的组参数来自原始权重），
  这是 GPTQ 的常规行为；本工具不迭代重估 scale。
- 对称网格零点固定，范围外没有额外余量，因此 8bit 对称偶尔比非对称略差。
- 耗时随列数大致平方增长（1536 列约 0.5 秒，4096 列约 2.6 秒）。
